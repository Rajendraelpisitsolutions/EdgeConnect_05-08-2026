**Status:** v2 — locked (ChatGPT review folded in)

## 1. Goal

Make hot-reload converge runtime state for instances **skipped from the supervisor at startup** by M.P2.1 fail-soft validation. Today: source registers `CONFIG.SOURCE_WITHOUT_ROUTE` at boot → operator adds the missing route via Apply → coordinator only sees `Added(Route)` in the diff → source is never re-attempted → both source and route end up faulted. M.P2.2 phase 3 documented this as a workaround (`docs/ops-runbook.md` §5).

M.P2.3 closes the seam by having the coordinator synthesize recovery actions when cross-record validation flips from invalid → valid. The workaround goes away.

### Architectural pin (locked)

**M.P2.3 extends M.P2.2 without modifying its diff-classifier purity guarantees.** `RuntimeReloadClassifier` remains a pure function of `(newConfig, changes)`. Recovery synthesis is a coordinator-layer concern; it operates against the registry under the same reconcile semaphore but never reaches back into the classifier. ADR-0010 captures this lock.

---

## 2. The seam (precise statement)

After M.P2.1 startup, a source that fails cross-record validation is:

- Recorded in `IConfigurationFaultRegistry` with the failure code (e.g. `CONFIG.SOURCE_WITHOUT_ROUTE`).
- **NOT added to `SourceSupervisor`** — the supervisor doesn't know it exists.

After M.P2.2 the `RuntimeReloadCoordinator` processes plan-driven actions from `RuntimeReloadClassifier`. The classifier is a pure function of the diff — it emits actions only for entities whose own config changed. If only the *route* changes (the source itself is unchanged), no source action is generated, B1 doesn't run for the source, and the source never gets re-tried.

Each layer is correct in isolation. The combination produces a permanent stall until the operator forces a `Modified` change on the source.

## 3. Locked decisions

### Carry-forward from v1 (unchanged after ChatGPT review)

| # | Decision | Reasoning |
|---|---|---|
| A | The fix lives in the **coordinator** as a pre-pass, NOT in the classifier | Classifier is locked as a pure function of `(newConfig, changes)`. Coordinator already owns fault-registry interaction (`ClearFor` on success). Adding fault-registry input to the classifier would break purity, couple replay/debugging to registry state, and make diff semantics non-local. |
| B | Synthesis produces `ReloadOp.Add` actions, NOT `Restart` | The skipped source was never running. `Restart` semantically means "stop + start"; for a never-started instance, the teardown half is a no-op and the wording is misleading. `Add` is correct. |
| C | Cross-record validity is recomputed **inline** against `newConfig`, NOT by re-running the M.P2.1 startup validator | Startup validators are boot-oriented, broader in scope, fault-producing, and potentially side-effectful. Coordinator needs narrow, deterministic, allocation-light, pure predicates. |
| D | Symmetric handling: synthesize for Source, Sink, AND Route faults | The seam exists for all three. A `CONFIG.ROUTE_REFERENCES_MISSING_SOURCE`-faulted route also stays faulted after a source-add Apply. |
| E | License-disabled instances are **out of scope** | License state doesn't change via Apply; license-blocked instances use a different signal channel. Separate concern. |
| F | Synthesis runs BEFORE plan execution, INSIDE the reconcile semaphore | Coordinator already holds the semaphore. Inserting at the top of `ReconcileAsync` keeps everything under the same single-flight guarantee. |
| G | Reload-outcome surface treats synthesized actions identically to classifier-emitted actions | A synthesized Add that succeeds → `AppliedInstances`. A synthesized Add that faults → `FaultedInstances`. No new `RecoveredInstances` / `SynthesizedActions` field on `ReloadOutcome`. Operator cares about "did it come up", not how the coordinator decided to try. |

### Added at v2 lock (ChatGPT review)

| # | Decision | Reasoning |
|---|---|---|
| H | **Synthesized actions are ephemeral.** `plan.Actions` (the classifier output) is never mutated. The coordinator computes `effectiveActions = plan.Actions ∪ synthesized` as a local and drives orchestration off that list. | Preserves the classifier's pristine output for downstream inspection / debugging / logging. A future audit-chain debug pass can cleanly compare "what the operator changed" vs "what the coordinator added on top". Folding loses that distinction. |
| I | Synthesis precondition includes "entity is **not already active in the relevant runtime registry / supervisor**" | Routes live in `_routingEngine`, sources in `_sourceSupervisor`, sinks in `_sinkSupervisor` — each has its own membership check. Without this guard, a stale registry entry could trigger duplicate Add → noisy logs → false fault churn. |

### Synthesis precondition (full, locked)

Synthesize an `Add` action for `(fault.Kind, fault.InstanceId)` if and only if **all** of:

1. **Fault exists** in `IConfigurationFaultRegistry` with one of the three in-scope error codes (Q1 below).
2. **Cross-record validation now passes** against `newConfig` (the inline predicate per locked C).
3. **Entity still exists in `newConfig`** (operator hasn't removed it).
4. **Entity is NOT already active** in the relevant runtime registry/supervisor (locked I).
5. **No classifier action already targets** `(kind, entityId)` — dedup by key (locked Q3).

## 5. Out of scope (explicit guardrails)

- **No classifier change.** Classifier stays a pure function of the diff.
- **No new `ReloadOp` value.** Reuse `Add`.
- **No mutation of `plan.Actions`.** Per locked H. The classifier output is immutable downstream.
- **No new audit actions.** Synthesized actions audit the same way as classifier-emitted ones.
- **No license-state recovery.** License-disabled instances are not in scope.
- **No deeper "any fault could be recoverable" logic.** Strictly the three Q1 codes.
- **No fault TTL or independent auto-clear pass.** The existing `ClearFor` on successful re-init still does the clearing.
- **No new reload-outcome fields.** Synthesized actions flow through the existing Applied/Restarted/Faulted lists transparently.
- **No UI / Studio badge for "synthesized vs operator-driven".** Operator UX is unchanged.

### Pseudocode ordering (locked, per ChatGPT recommendation)

```
ReconcileAsync(e):
    1. Stale-version skip → EnqueueSkipped, return
    2. stopwatch.Start()
    3. plan = RuntimeReloadClassifier.Classify(...)        # pristine, never mutated
    4. synthesized = ComputeStartupSkipRecoveryActions(plan, newConfig)
    5. effectiveActions = plan.Actions ∪ synthesized        # ephemeral
    6. if effectiveActions.Count == 0:
           EnqueueCompleted (NoOp, empty lists)
           return
    7. A1/A2/A3 teardown over effectiveActions
    8. B1/B2/B3 bring-up over effectiveActions
    9. EnqueueCompleted with populated outcome
```

## 9. Risks & mitigations

| Risk | Mitigation |
|---|---|
| M.P2.1 validator emits codes not in the assumed Q1 set | Step 1 of §7 reads the validator first; lock the set against reality before writing synthesis logic. |
| Synthesis fires for a fault whose entity was deleted from `newConfig` | Precondition #3 explicitly requires the entity to still exist in `newConfig`. Test #2 covers. |
| Stale-version skip + synthesis interaction across rapid Applies | Stale-version-skip (M.P2.2 phase 2.c) handles ordering. By the time the later reconcile starts, the earlier one is complete; precondition #4 (already-active check) catches the duplicate-Add case. |
| Synthesis pass extends per-reconcile latency budget | Pass is O(faults) × O(entities). Faults ≤ low tens, entities ≤ low hundreds. <1 ms in practice. ElapsedMs comment from Phase 3 already covers this. |
| Supervisor membership check (precondition #4) returns false positive during a concurrent teardown | Reconcile is single-flighted via the semaphore; teardown and bring-up don't run concurrently with synthesis. If a future change makes them concurrent, revisit. |
| `EnumerateActions` signature refactor breaks an unforeseen consumer | The function is private to `RuntimeReloadCoordinator`; only five call sites internal to the class. Step 3 regression gate catches any miss. |

## 12. ADR-0010 outline (preview)

Will land at `docs/decisions/0010-coordinator-synthesizes-cross-record-recovery.md`.

**Title:** Coordinator synthesizes Add actions for cross-record validation flips

**Status:** Accepted (2026-05-17)

**Context:** M.P2.1 fail-soft skip + M.P2.2 plan-driven coordinator = sources / sinks / routes that fail cross-record validation at startup remain stalled after a route-only Apply. The diff doesn't contain an action for the entity, so the coordinator never re-tries it. Documented as a workaround in ops-runbook §5 by M.P2.2 phase 3.

**Decision:**
1. The coordinator runs a synthesis pre-pass before each reconcile.
2. For each fault in `IConfigurationFaultRegistry` with one of `CONFIG.SOURCE_WITHOUT_ROUTE` / `CONFIG.ROUTE_REFERENCES_MISSING_SOURCE` / `CONFIG.ROUTE_REFERENCES_MISSING_SINK`, the coordinator inline-checks whether the entity's cross-record validity has flipped to OK against `newConfig`.
3. Where it has, the coordinator emits a synthetic `Add` action and routes it through the existing A1-A3 / B1-B3 phases.
4. `RuntimeReloadClassifier` is unchanged. The classifier output (`plan.Actions`) is never mutated. Synthesized actions are ephemeral via `effectiveActions = plan.Actions ∪ synthesized`.

**Reasoning:**
- Classifier purity preserved; coordinator owns runtime convergence. The split established in M.P2.2 (config intent vs. runtime projection) is reinforced.
- Inline predicates over invoking startup validators — narrow, deterministic, pure.
- `Add` over `Restart` — semantically correct for a never-started entity.
- Synthesized actions identical to classifier-emitted ones in the reload-outcome surface — operators see "did it come up", not "how it was decided".

**Consequences:**
- `EnumerateActions` refactored to take `IReadOnlyList<ReloadAction>` instead of `ConfigurationReloadPlan` (private signature change).
- New synthesis precondition is the load-bearing invariant; documented above and pinned by Test #2 + Test #3 + Test #5.
- The ops-runbook workaround is removed.

**Header framing line** (per locked Q6 / ChatGPT review):
> ADR-0010 extends ADR-0009 without modifying its diff-classifier purity guarantees.
