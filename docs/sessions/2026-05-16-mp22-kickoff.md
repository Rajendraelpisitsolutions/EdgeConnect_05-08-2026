# Session kickoff — M.P2.2 (Runtime hot-reload)

**Date:** 2026-05-16
**Branch:** `claude/m-p2-2-hot-reload` off master @ `546327a`
**Prior milestone:** M.P2.1 (fail-soft startup) — merged to master at `546327a`
**Estimated size:** 3 commits, ~800-1200 LOC + ~600-700 LOC tests
**Test baseline:** 1616 → expected ~1696-1721 after M.P2.2

## Why this milestone

After M.2a, the Studio's Apply button rewrites `current.json` and emits
a `CurrentChanged` event — but **no host subscriber exists**.
`Core/Configuration/ConfigurationManager.cs:397` is the boundary; past
that line the runtime still uses the boot-time config. Operators must
restart the gateway after every Apply.

M.P2.2 wires a `RuntimeReloadCoordinator` into the host that reconciles
the live supervisor / routing-engine state with each applied config,
reusing the M.P2.1 fault plumbing for reconcile-time failures.

This delivers the full UX promise of the M.2a draft → validate → apply
flow, and unblocks every wizard milestone after this one (M.5a Device
Inspector, M.2b.2 S7 wizard, M.2b.3 FOCAS2 wizard) — wizards become
much less painful when Apply doesn't restart the gateway.

## Locked decisions

All 10 architectural choices are signed off (ChatGPT review pass,
2026-05-16). The four most-locked are captured in **ADR-0009**; the
remaining six are implementation choices documented inline below.

| # | Decision | Lock |
|---|---|---|
| A | Reload granularity: **per-instance** (not per-route) | ADR-0009 |
| B | Apply policy: atomic validate, best-effort reconcile | This doc |
| C | Lifecycle order: **routes first on teardown, routes last on bring-up** | ADR-0009 |
| D | Modify == Stop-then-Start in v1 (no `ITryReconfigureLive`) | ADR-0009 |
| E | Coordinator threading: own `SemaphoreSlim(1,1)`, NOT the apply mutex | This doc |
| F | API: extend `ApplyResultDto.Reload: ReloadOutcomeDto?` (not a flag) | This doc |
| G | Audit-chain actions: reuse `Applied` + `RuntimeConfigurationFault` | This doc |
| H | ADR-0007 display precedence: unchanged | This doc |
| I | Test harness: extend existing `HostHarness` | This doc |
| J | **No auto-rollback on reconcile failure** | ADR-0009 |

### Stop / start order (from ADR-0009 Decision 2)

```
Remove / Restart (teardown):
  1. Stop affected routes
  2. Stop removed or now-unreferenced sources
  3. Stop removed or now-unreferenced destinations

Add / Restart (bring-up):
  4. Start sources (bounded channel buffers any early points)
  5. Start destinations
  6. Start routes (wires source intake → fanout → sinks; dispatch begins)
```

A sink referenced by N routes (per the M.P2.1 phase 3b
`SinkListItemDto.RouteIds` model) is stopped only when N drops to zero.

### Phase 2 — Supervisors gain runtime mutation + Host coordinator (commit 2)

**Scope.** Supervisors learn per-instance add/remove/restart. New
`RuntimeReloadCoordinator` in the host subscribes to `CurrentChanged`,
classifies the diff, drives supervisors + routing engine, registers /
clears faults, writes runtime-fault audit entries.

**Deliverables:**

| File | Change |
|---|---|
| `src/ElpisEdgeConnect.Host/Adapters/SourceSupervisor.cs` | New `AddAsync(reg, ct)`, `RemoveAsync(id, ct)`, `RestartAsync(newReg, ct)`. Internal `_supervised` → `ConcurrentDictionary` + per-instance CTS. |
| `src/ElpisEdgeConnect.Host/Adapters/SinkSupervisor.cs` | Mirror set. `_registrations` keyed by instance id. |
| `src/ElpisEdgeConnect.Host/Adapters/RegistrationFactory.cs` *(new)* | Protocol dispatcher: `(SourceInstanceConfig, GatewaySettings, license, faultRegistry) → SourceRegistration?`. Same for sinks. Extracted from the per-protocol `*RegistrationExtensions.FromGatewayConfig` methods so the coordinator can build a single instance's registration without going through DI. |
| `src/ElpisEdgeConnect.Host/RuntimeReloadCoordinator.cs` *(new)* | The orchestrator. Subscribes in `StartAsync`, unsubscribes in `StopAsync`. Handler runs `_ = Task.Run(() => ReconcileAsync(e))` to never block the apply mutex. Reconcile holds own `SemaphoreSlim(1,1)`. Executes plan in the locked stop/start order. Per-instance failures register faults + continue. |
| `src/ElpisEdgeConnect.Host/HostStartup.cs` | Wire the coordinator after `MarkReady` so the gateway doesn't react to a `CurrentChanged` mid-boot. Symmetric unsubscribe on stop. |
| `src/ElpisEdgeConnect.Host/CompositionRoot.cs` + `EdgeConnectComposition.cs` | Register `RuntimeReloadCoordinator` singleton; pass through the existing fault registry instance. |

**Test target:** ~35-45 tests. Per-instance supervisor add/remove/restart (isolation, channel re-construction); coordinator tests with substituted supervisors verifying the locked stop/start order; integration in `HostHarness` driving a full apply → reconcile cycle on mock adapters.

**Risks:**

1. **Adapter init blocking on bad config.** Modbus dials the device in `InitializeAsync`. Mitigation: per-instance 30s reconcile timeout → fault `HOST.RECONCILE_TIMEOUT` + continue.
2. **Channel completed-then-resumed.** `SourceSupervisor.StopAsync` calls `Channel.Writer.TryComplete()`. Re-adding the same instance id must construct a brand-new bounded channel, and `RouteDefinitionFactory.Build` must run *after* the supervisor add completes so the intake resolves to the new channel.
3. **MQTT/OPC UA Server connection churn on restart.** External clients see a disconnect/reconnect blip. Store-and-forward holds points across the gap. Document this in the apply response's `ReloadOutcome` (per-instance restart duration).

## Definition of done (exit checklist)

Modelled on Phase 1's exit pattern:

1. **Code.** All three phases on master via `--no-ff` merge commits.
   `dotnet build ElpisEdgeConnect.sln` is 0 warnings, 0 errors.

2. **Tests.** `dotnet test --filter "Category!=Flaky"` passes. Total
   ~1696-1721 (1616 baseline + ~80-105 new). Core coverage stays ≥80%;
   new Host code reaches ≥75%.

3. **Locked-decision tests.** Named tests fail loudly if any of these
   are violated:
   - Lifecycle order: routes stop first, sources/sinks stop second
   - Lifecycle order on add: routes start last, after sources + sinks
   - Modified instance → Stop-then-Start (no in-place reconfigure)
   - Reconcile failure → registers fault + audit entry; subsequent
     successful re-init clears the fault
   - Coordinator is single-flight (two near-simultaneous applies queue)
   - Apply succeeds even when reconcile fails (no auto-rollback)

4. **Smoke test.** Against `Management.exe` and the poison config at
   `%LOCALAPPDATA%\edgeconnect-uademo\config\` (primed in M.P2.1 phase
   3b handoff):

   1. Boot gateway. Baseline: `modbus-demo` Running, `modbus-line-2`
      Disabled, `modbus-line-3` Faulted (`MODBUS.SOCKET_ERROR`),
      `Modbus-4` Faulted (`CONFIG.SOURCE_WITHOUT_ROUTE`).
   2. Draft a config that:
      - Adds new Modbus source `modbus-line-5` with a valid route
      - Removes `modbus-line-3` (runtime-faulted one)
      - Modifies `modbus-demo`'s polling cadence (1000ms → 500ms)
      - Fixes `Modbus-4` by adding the missing route
   3. Apply. Without restarting the gateway, verify:
      - `modbus-line-5` appears as Running within 5s
      - `modbus-line-3` disappears from `/sources` and from the
        `/diagnostics` Configuration-faults panel
      - `modbus-demo` metrics rate doubles (poll cadence change)
      - `Modbus-4` transitions Faulted → Running
   4. Apply a *broken* draft (Modbus source with unreachable
      host:port). Verify:
      - Apply succeeds (config durable)
      - `ApplyResultDto.Reload.FaultedInstances` contains the new id
      - `/diagnostics/configuration-faults` shows a row with
        `MODBUS.SOCKET_ERROR`
      - Existing sources unaffected (per-adapter isolation)

5. **Docs.** ADR-0009 committed (this branch, first commit).
   `docs/ops-runbook.md` and `docs/config-authoring.md` updated in
   phase 3. End-of-session handoff doc when M.P2.2 closes.

## Explicitly out of scope

- **Schema migrations.** New top-level config blocks the runtime
  doesn't understand still fail schema validation at apply time.
- **OPC UA Server session preservation across sink restart.**
  Clients see a disconnect / reconnect; auto-reconnect within seconds.
  Documented as a known limitation.
- **License-tier hot-reload.** `ILicenseManager` is loaded eagerly at
  composition; license file changes still require a restart.
- **`ITryReconfigureLive` adapter opt-in.** Future optimisation per
  ADR-0009 Decision 3 — only if a real operational pain emerges.
- **Drain-aware sink shutdown on route remove.** Bounded by the existing
  10s graceful-stop timeout from the `ISinkAdapter` contract.
- **Studio "rolling apply preview"** (which instances will restart
  before Apply). Surfacing post-apply outcome is enough for v1.
