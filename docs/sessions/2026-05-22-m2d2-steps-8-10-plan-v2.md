### 0.2 CORRECTION — 409 discriminator (the v2 architectural delta)

v1 proposed the wizard's response handler "try `ConfigVersionMismatchDto` deserialise first, fall through on failure" to discriminate the two 409 cases (version mismatch vs apply-time validation failure).

**v2 verdict: brittle. Add an explicit discriminator field.**

`ConfigVersionMismatchDto` gains a `ConflictType` field with the locked value `"VersionMismatch"`:

```csharp
public sealed record ConfigVersionMismatchDto
{
    /// <summary>
    /// Locked discriminator: always "VersionMismatch". Lets the client
    /// distinguish this 409 body shape from the other 409 case
    /// (revalidation-failed-under-apply-mutex returns ValidationResultDto).
    /// </summary>
    public string ConflictType { get; init; } = "VersionMismatch";

    public required string BaseVersionId { get; init; }
    public required string CurrentVersionId { get; init; }
    public required DateTime ChangedSinceUtc { get; init; }
}
```

Wizard client discriminates by reading the JSON property `conflictType`:

```csharp
// Pseudocode in SaveEditAsync's 409 branch
if (resp.StatusCode == HttpStatusCode.Conflict)
{
    var rawJson = await resp.Content.ReadAsStringAsync();
    using var doc = JsonDocument.Parse(rawJson);
    if (doc.RootElement.TryGetProperty("conflictType", out var ct) &&
        ct.GetString() == "VersionMismatch")
    {
        _staleEditMismatch = JsonSerializer.Deserialize<ConfigVersionMismatchDto>(rawJson);
        return;
    }
    // Other 409 — apply-time revalidation failed.
    var validation = JsonSerializer.Deserialize<ValidationResultDto>(rawJson);
    Snackbar.Add($"Save rejected at apply time: {validation?.Errors?.FirstOrDefault()?.Message ?? rawJson}", Severity.Error);
    return;
}
```

This requires no shape change to `ValidationResultDto` (existing contract preserved). The discriminator lives on the new DTO; absence of the discriminator implies the existing-shape DTO.

The `ConflictType` default value of `"VersionMismatch"` is the only valid value — there is no setter use case; the field is constant-on-this-DTO. The init-default pattern keeps records-with-friendly while documenting the discriminator role.
