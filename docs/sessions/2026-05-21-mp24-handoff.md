## 4. Architectural invariants preserved

- **§2 no-leak invariant.** Production `src/ElpisEdgeConnect.Sources.BrotherHttp/` does NOT reference legacy `ElpisEdgeConnect.Models` types. Only the test project's `LegacyCanonicalMapper` consumes `CncMachineData`, and only as a parity oracle.
- **§5 structural-purity contract.** `BrotherTagMapEntry` exposes exactly five members (TagName / TagPath / ValueType / Unit / Description). A reflection-based contract test fails loudly if any future PR adds a legacy-coupled member (LegacyFieldName, value transform, etc.).
- **§6.4 catalog evolution rule.** Catalog is append-only and semantically stable within the M.P2.x line. Renaming a path requires a milestone bump + downstream consumer migration plan.
- **v3.1 §B determinism + observability locks** all wired into `BrotherHttpSourceAdapter`:
  - §B.1 atomic batch (one `IReadOnlyList` per cycle)
  - §B.2 single timestamp at cycle start (`DeviceTimestamp == GatewayTimestamp`)
  - §B.3 single-flight via `Interlocked.CompareExchange`; overrun → empty + metric
  - §B.4 no fire-and-forget Tasks
  - §B.5 metrics surface: `elpis_edgeconnect_brother_poll_duration_ms` histogram + `elpis_edgeconnect_brother_endpoint_failures_total` counter + `elpis_edgeconnect_brother_poll_overruns_total` counter; outcome label `success | degraded | failed`
- **Parity discipline.** `LegacyCanonicalMapper` reads `CncMachineData` independently from the new collectors so any drift between protocol semantics and a legacy parser quirk surfaces as a test failure rather than being silently aligned.

## 5. Documented divergences (carried forward as-is)

Two "new-adapter-only" canonical extensions are intentional and documented in v3 §6 + this handoff. The parity test uses subset (legacy ⊆ new) rather than strict equality to accommodate them.

| Divergence | Reason | Risk |
|---|---|---|
| `MachineInfo/StatusCode` | Legacy parses raw 0-5 but discards it before storing in `CncMachineData`. New adapter emits it as a canonical tag. | None — new emission is strictly additive. |
| `Tools/Magazine/{slot}/*` (slot-keyed) | Legacy stores tool numbers in `ToolInfo.Offsets[]` (list order) but NOT the parsed magazine slot numbers. New adapter emits slot-keyed paths from the response. Tool-number-keyed `Tools/Tool/{toolNo}/Name|Type|Life` are preserved on both sides. | None — slot-keyed paths are new canonical content; legacy didn't carry them so there's no consumer expectation to break. |
