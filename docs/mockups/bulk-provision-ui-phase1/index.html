State 9 — Error states

v3 §4 block/warn matrix + v3.1 §5/§6

Nine blockers + three warnings per v3 + v3.1. All include the offending row identified + operator-readable fix.

Duplicate deviceId within CSV
Block — 1 row in CSV. Row 7 and row 12 both have deviceId=cnc-031. Each deviceId must be unique within the upload.

Code: BulkProvision.CsvDuplicateDeviceId
Existing source InstanceId collision
Block — 2 rows collide with existing sources. Row 7 (cnc-007-source) and row 8 (cnc-008-source) already exist on this gateway. Either rename, remove from CSV, or delete the existing source first.

Code: BulkProvision.SourceInstanceIdCollision
Existing source DeviceId collision (re-import)
Block — operator likely re-imported same device. Row 4 has deviceId=cnc-031 but a source for that DeviceId already exists (cnc-031-source, "Lathe-Bay-5"). DeviceId is the operational identity; importing the same one twice is a mistake.

Code: BulkProvision.SourceDeviceIdCollision
Invalid MTConnect baseUrl
Block — 1 row has malformed baseUrl. Row 7 (okuma-vmc-7): 192.168.10.57:5000 is not an absolute URL. MTConnect baseUrl must start with http:// or https://.

Code: BulkProvision.MtConnectBaseUrlInvalid
Invalid deviceId format
Block — 3 rows have invalid deviceId. Row 3: cnc 007 (space). Row 8: cnc/007 (slash). Row 14: cnc.007 (dot). deviceId must match ^[A-Za-z0-9_-]+$, length 1–64.

Code: BulkProvision.DeviceIdFormatInvalid
Stale preview / config changed
Block — config changed since preview. Someone else applied a draft after you generated this preview. Please refresh the preview to review the new gateway state before submitting.

Code: BulkProvision.BaseConfigHashMismatch
Generated config fails schema validation
Block — generated merged config did not validate. The merged GatewayConfiguration failed schema validation. Common causes: a CSV value contains an unexpected character that broke the rendered JSON (e.g. an unescaped backslash in deviceName); a recently modified protocol template produced invalid output. Re-check the offending row above; if everything looks normal, capture the import label fanuc-batch-2026-06-14 and contact platform support.

Code: BulkProvision.MergedConfigSchemaViolation
Invalid CSV header / extra column
Block — CSV header does not match the expected shape. Expected columns: deviceId, deviceName, host, enabled (FOCAS2 / Brother / Modbus) or deviceId, deviceName, baseUrl, enabled (MTConnect). Found extra column tagProfile. Per v3.1 §8 the wizard does not accept extra columns; they would silently bypass validation. Remove unknown columns or download the protocol's CSV template.

Code: BulkProvision.CsvHeaderShapeInvalid
Generated RouteId collision
Block — generated RouteId already exists. Row 4 would generate RouteId = route-cnc-031, but that route already exists on this gateway (pointing at cnc-031-source). Either rename the imported row's deviceId, delete the existing source/route pair, or remove the row from the CSV.

Code: BulkProvision.RouteIdCollision

Warnings (do not block; surface in upload preview)

Duplicate deviceName in CSV
Warning — 2 rows share deviceName. Row 3 (cnc-033) and row 12 (cnc-042) both named "Lathe-Bay-7". Operationally identifiable by deviceId; this is allowed.
Duplicate Route Name
Warning — 1 generated Route Name matches an existing route. Row 7 (cnc-037) would generate "Mill-A3 to edge-acme-mqtt", which matches the name of an existing route. Routes are uniquely identified by RouteId (which is unique here), so this is allowed; duplicate names can make the Routes page harder to read but don't affect operation. Per v3.1 §4.
Unapplied draft already exists
Warning — this gateway has an unapplied draft. Draft #138 (created 2 hours ago) is still pending review. Submitting this import will create draft #142 alongside it. Either apply or discard #138 before applying #142 to avoid confusion about which change takes effect.
